# 创作教训簿（每完成一篇追加）

> **用途**：经验回流。每完成一部作品，把审校、连续性、文风体检、发行与读者反馈中暴露的问题，
> 压成**一条可执行的规则**追加到本文件；流水线在 concept / world / draft / review / revise / continuity
> 六个阶段自动注入本文件（归属 `09-质量规则` 模块）。
>
> **写法要求**：一条教训 = 现象（哪部作品）→ 根因 → 今后怎么做 → 检查手段（自动化/人工）。
> 禁止写「要写好一点」这类空话；禁止只记现象不记规则。

## 一、结构类

1. **复制章**（《意识纪元》4/5、13/14；《地球2200》4/5：同一场戏换个名字又写一遍）
   → 每章必须推进不同事件，重复桥段一律重写。
   → 检查：跨章 5 字滑窗相似度检测（`lint`），连续性机器预检。
2. **多重收尾**（《喂饭》：写完「（全文完）」又被字数闸门续写出一整套结尾）
   → 检出完结标记后一律停止续写；结尾只保留一套。
   → 检查：完结标记 + 标记后正文长度检测。
3. **续写复述/重启**（《销号》：续写把整篇从头重写了一遍，正文出现两遍）
   → 续写不得复述章尾、不得搬用开篇整句；违反即拒绝拼接。
   → 检查：`continuation_repeats` / `continuation_restarts` 护栏。
4. **转折来自巧合或外力**（《借脸》初稿：巷子里凭空出现一个「修卡的人」帮主角续命三天）
   → 短篇的唯一转折必须来自主角自己的选择；禁止天降救兵、禁止巧合翻盘。
5. **没有反派 ≠ 没有冲突**（《责任官》第一稿：全篇只有主角对着屏幕签字）
   → 必须写出**对立的好 + 稀缺资源 + 时限 + 会开口的代理人**，至少三场活人对峙，每场都有代价。
   → 检查：审校清单新增「活人冲突」一项；写前先填冲突表。
6. **结尾说教**（《借脸》模型修订稿自行补了一句倒计时式总结）
   → 结尾禁止解释性句子、禁止主题升华；模型修订稿要逐句检查结尾。
7. **单一效果失守**（短篇被写成缩小版长篇）
   → 短篇只服务一个印象：一个主角、一个处境、一个转折、一个余味。

## 二、语言类

1. **AI 腔与套话密度**（早年五部长篇 D 级：微微/仿佛/某种/深吸一口气/不是…而是…成灾）
   → 写作时禁用清单入红线；旧作按体检报告定向重写。
   → 检查：`lint`（套话、AI 腔句式、虚词密度、高频四字串）。
2. **填充词**（微微、缓缓地、轻轻地、一种…的…、某种…的…）
   → 确定性瘦身：只在白名单搭配下删除，不做同义替换。
   → 检查：`lint --fix`（原稿存 .bak，前后对比体检分）。
3. **检测误报**（「长时间静止」被当成「时间静止」套话）
   → 套话命中要加前缀排除表；宁少报，不误伤。
4. **长句长段、说明文堆积**（infodump）
   → 单段技术说明 ≤200 字；长句在转折处断开；规格数字要省着用。
   → 检查：句长/段长指标 + 审校红线。
5. **术语过载**（《责任官》初稿 8,646 字，协议条款与传感器规格淹没人物）
   → 规格是调味，人物的账才是主菜：每章科技/制度细节只保留能改变选择的那几处。

## 三、真实题材类

1. **真实新闻必须去标识**（人名、机构、商品、平台、地名全部虚构）
   → 每篇写 `00-选题来源.md`：新闻事实、挑选理由、改变对照表、红线。
2. **先立底稿再写小说**（淮滨、免费经济、传统知识、农膜）
   → 真实结构用真的、制度推演标注虚构；底稿进 `knowledge/11-社会推演`。
3. **政策类新闻要留「半截结局」**（抬头率：不再统计，但摄像头还在）
   → 制度不会因一篇报道彻底改变；忠实比痛快更有力。
4. **数字要与正文对账**（38 亩/20 亩事故：正文改了，设定文档没跟上）
   → 正文是唯一权威；改数字先改正文，再回改设定文档。

## 四、读者性类（来自读者反馈，优先级最高）

1. **「风格太安静没人看」** → 开篇必须有钩子：悖论句、倒计时或一个反常数字；
   前 200 字给出麻烦与代价，先让人物行动，再让读者推断规则。
   （正例：《个案》「三十七个人还活着。系统说，这叫个案。」）
2. **「必须思辨」** → 每篇至少一个**可争论**的核心问题，一句话能写进评论区；
   正文里让正反双方真刀真枪辩一场，**反方必须有道理、有数据、有难处**。
3. **对赌结构** → 给主角一个 deadline 与两难选项，两边都有具体代价；转折的不可撤回性为零。
4. **可转述性** → 每篇至少一处让读者想转述给别人听的设定或细节。
5. **短篇仍只有一个转折**，但转折要「重」：读完之后人物回不到原处。
6. **钩子＝一组有落差的数字**（《挂牌》：「买的时候七十二万。今天出价三十九万」）
   → 第一句就给读者一把算盘，他会自己开始算；数字要能对上账、经得起心算。
7. **辩论必须落进对白**（《挂牌》31% 对白承担四场辩论）
   → 纯叙述的思辨没人读；让每一方用自己的行话、自己的数字，当面说。
8. **对手的账也要算**（《挂牌》买家自述「退了江州认购书，赔了四万」）
   → 让对立一方的损失先亮出来；主角的选择才会显得重，而不是赢。
9. **把道德选择标价**（《候场》：清场补偿一万二＝女儿首付的缺口，签了首付齐，不签就差一万二）
   → 读者不靠感动，靠算账；每一笔拒绝都要对应一个具体的人名与金额。
10. **机器要有胜绩**（《候场》算法第六次成相 81%，主角无话可说）
    → 科幻里的系统若从不赢，读者不信它的可怕；先让它赢一次，主角后面的输才有重量。
11. **让被编排者与编排者互为镜像**（《候场》：鹤被排成形状，市民被排成「一分钟笑几次」的指标）
    → 同一个制度同时处理鸟和人；两处一呼应，思辨自动成立，不用旁白点题。
12. **制度的辩词要能算账**（《候场》：三百二十个频道、九十秒、堤防三个亿、评级备忘录备注栏）
    → 反方不威胁、只给方案与数字；读者自己会算出恐惧。
13. **标题要有一个实体化的落点**（《候场》：旗上绣的是一只鹤，不是鲲鹏）
    → 书名是概念时，全篇必须有一个实物替它落地，且这个实物在结尾出现。
14. **结尾用「旧物」不用「新话」**（结尾落在旧旗、叫号屏、饭盒上）
    → 结尾不解释主题，只把读者已经认识的东西再拿出来一次。
15. **会议/仪式类新闻＝「全城排练」母题**（APEC 峰会 → 《候场》）
    → 会议新闻天然自带倒计时、镜头、全市动员与外客视线，是科幻最好的现实骨架之一。

## 六、科幻专项类（新增，2026-11）

1. **科幻不靠奇观，靠规则落地**（《候场》：声波阵列、灯阵、宜观度全部写成可算的条款与限制）
   → 每个设定先问三件事：谁用它、它花多少、它不能做什么。答不出就删。
2. **反拟人化**（城景台只给评分与选项，不「想」、不「犹豫」、不「愤怒」）
   → 系统的可怕来自它的机制，不来自它的情绪。
3. **近未来用今天的技术栈推十年**（宜观度、行为建议推送、环志监测、多语种终端）
   → 不用全息城市与飞船；把今天的系统加一层考核口径，就是近未来。
4. **一次只推翻一件事**（《候场》只推翻「把活物填进画里」这一件事，其余制度保持运转）
   → 全面崩塌没有说服力；局部被拒绝，才能逼读者想「那其余的谁来管」。
5. **让主角的失败留下可继续的账单**（赔付 12 万、住院自费 1 万 4、候诊 142 号、婚礼推迟）
   → 故事结束不等于账结束；结尾的清单越具体，余味越长。
6. **一人称视角的科幻更冷**（限定视角＋大量可量细节＝科幻感来自信息密度，不来自词藻）
   → 全篇第三人称有限，靠数据与细节制造距离感。

## 七、审校与一致性类（新增，2026-11）

1. **审校报告要逐条落实，不是参考**（《候场》一轮审校抓出时间线闭环、声波推鸟的物理硬伤、视角越界、金额与设定不符，每条都带位置与改法）
   → 有位置的条目逐条改，不讨价还价；改完重跑 `lint` 与 `audit`，直到体检分回到 100。
2. **物理机制先查常识**（声波不可能「推」动五公斤的鹤）
   → 写完设定先问「这东西在现实里到底靠什么起作用」；若答案需要额外假设，就换成更可信的机制（假的警戒鸣—恐惧规避），并把限制写进正文（130 dB 鸟耳膜出血、次日飞不高），让限制成为剧情。
3. **数字基线要四处同步**（正文 / 世界观 W 表 / 大纲 / 概念与投稿说明）
   → 改一个数字要全库搜一遍；把基线写进大纲首部，审校前逐项对账（《候场》1.2 万→1.4 万改了正文忘了概念稿，被审校逮住）。
4. **年份与角色年龄要对账**（2126 年出现「2019 年」的驱离单，而签字人只有 34 岁）
   → 近未来故事最易把现实旧年份照抄；凡是文件编号、事故年份、签字年份，都用故事年份重算，再核对角色年龄能否签字。
5. **视角不越界，用设备小屏代替**（《候场》许一在会场看到的那九十秒，改由控制箱侧面的导播信号回传小屏呈现）
   → 既守住「一章一视角」，又回答「他怎么知道」；设备是视角合法性的现成工具。
6. **审校模型也会误判，要人工裁决**（《候场》：它把「未来时任务通报」当成闪回矛盾；两次把「下一条」「模型算的就是这个」误报成跨章重复，而这两句全书其实各只出现 1 次）
   → 报告是线索不是判决：与大纲基线冲突的判定（81% 落在 D-6 还是 D-1）必须回查正文再确改；判定前先用脚本核一遍全书计数，别把"全书唯一"当成"跨章重复"去改坏。
7. **重复整句必查**（同一个动作句在同章出现两次）
   → `lint` 报「重复整句」即使只一处也要改；同章内换观察入口重写，不换同义词。
8. **把 LLM 的主观红线落成机器检查**（新增 `style.find_dup_quotes`：跨章重复台词＝名句配额）
   → 规则若可判定，就写进体检脚本，别每次靠模型投票：重复台词要豁免「功能性应答」与「称呼语」，否则噪声淹没真问题（《候场》一上线就抓出两处真重复：「你弄你的鸟」「一百四十二」）。

## 八、流程类

1. **手写优先**：模型初稿过载、跑偏或复述时，按骨架手写收束；模型修订稿常自行添加抒情尾句，须逐句删。
2. **锚点分离**：章节保留 W/C 锚点，出版净稿自动剥离；不要手工删。
3. **项目编号**：`projects/NN_书名`；`init` 自动分配序号，旧名仍可定位。
4. **端点不稳**：先跑离线检查（`lint` / 机器预检），再重试 `review` / `translate`；重试脚本可复用。
5. **经验回流**：每篇完成后把新教训追加到本文件；同一教训只记一条，出现新变体时补进同一条。
